# Repository Working Notes

## Markdown Diagrams

- When a Markdown document needs a diagram, write it as a Mermaid diagram.
- Prefer Mermaid for architecture flows, sequence diagrams, state transitions, component relationships, and use case relationships.
- Keep diagrams close to the section they explain, and add a short text explanation before or after the diagram.
- Do not use image files for diagrams unless there is a specific reason Mermaid cannot express the needed view.

## PPT Generation

- When creating or revising a PPT for this repository, use `PPT_DESIGN_PROMPT.md` as the default design system prompt unless the user explicitly provides a different design direction.
- Keep generated slides in 16:9 format.
- Do not use logos in generated slides.
